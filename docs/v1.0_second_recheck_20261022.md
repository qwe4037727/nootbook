## 阻塞发现

### S01 [P1] 导入重置后，旧初始化任务仍可把旧角色状态写入新书

位置：`internal/store/memory_init.go:205`（旧知识快照）、`:348`（重新读取初始化状态但未验证任务有效性）、`:385`（按新 meta 提交旧快照）。

`runMemoryMapping` 分别读取 knowledge/project/chapters，再获取 memoryMu 写记忆。`resetMemoryLocked` 虽然已正确获取 memoryMu，却没有取消旧任务或递增并验证任务所属的导入代次。因而一次合法交错如下：

1. 旧任务读取旧书知识快照，释放 store.mu。
2. 导入新书，清空 knowledge 和 memory，重置 init_state/meta，并返回。
3. 旧任务继续读取新项目/章节，进入 memoryMu，使用此前捕获的旧知识生成角色状态。
4. 旧任务读取新书 revision 0 并提交旧角色状态，重新写入初始化终态。

影响：新书出现旧书人物状态；单次文件操作互斥不能保证异步任务属于当前作品数据。

新增探针 `TestAcceptanceSecondRecheckImportDuringMapping` 连续 3 次复现：新书 states.json 出现旧角色 `c_old` / `old state`。探针设置与异步入口相同的 mapping 起始态，直接启动生产 worker，用互斥锁排队和较大的旧知识快照安排交错；没有修改生产代码或伪造写入后的结果。

修复要求：导入后必须使先前初始化任务失效；在提交及终态/失败回写前验证任务所属代次。可采用任务代次或等价的取消/串行化机制，不能仅依赖当前 memoryRevision（导入会归零）。验证旧任务不得写新书记录，也不得覆盖新书或新任务的 init_state。
