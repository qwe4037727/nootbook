# R4 召回质量：真实语料命中率复测与内核修复（2026-10-24）

本轮由 `task/r4-realcorpus-review.md` 的独立复审触发：那份复审在真实长篇语料上量到
「埋设→召回」命中率只有 5%–13%，而每一档都在为召回支付固定正文窗口成本。
本轮先用自己的探针复现，再改内核，再复测。语料、`output/` 与临时数据目录都在
`.gitignore` 内，本文件只记数字与章节序号，不抄正文。

## 1. 环境

- 二进制：`output/novelagent-ui.exe`（由 `go build -o output/novelagent-ui.exe .` 产出，`//go:embed web`，仅用于起服务）
- 监听：`127.0.0.1:8096`，数据目录 `output/r4-probe-data`（**未使用、未修改 `D:/go/data`**）
- 语料：`corpus/`（gitignore）里的一部真实长篇，UTF-8，177,295 rune、自动分章 79 章

- 探针：`r4_hit_probe.mjs`（埋点命中率 + 中性方向 5 次对照）、`r4_gate_check.mjs`（有/无线索对照）、
  `r4_vague_terms.mjs`（方向词 df 审计），三者已随本文件归档

## 2. 度量口径

对每一章做与内核同构的 2/3-gram 切分，取「全书只有这一章出现」的 n-gram 作为埋点候选，
按章去重后等间隔抽 26/29 个样本；把埋点词写进续写方向，调用预览，记：

- `targetRecalled`：埋点所在章是否出现在 `recallChapters`
- `termInjected`：埋点词是否出现在注入文本里（召回了章但片段没覆盖到词，也算未命中）
- `meanRecallUsedChars` / `meanManuscriptChars`：召回吃掉多少正文尾窗
- 中性方向 5 次重复：同一输入是否得到同一排序（确定性对照）

## 4. 根因与修法（全部落在 `internal/recall/recall.go`）

1. **存在性打分**：`tokenizeRunes` 返回集合，tf 恒为 1，反复使用的线索与只出现一次的线索同分。
   → 改为 `tokenCounts` 计数，BM25 用真实 tf 饱和（k1=1.5、b=0.75）。
2. **重叠面压过关键线索**：查询是最近正文 1200 rune 的尾窗，几百个 n-gram 全部相加，
   一条决定性线索比不过「和最近正文长得像」。→ 每个块只取贡献最高的 `ScoreTermLimit=3` 条。
3. **没有注入闸**：任何微弱重叠都填满 800 字。→ 块内必须命中一条「方向里的罕见线索」，
   罕见度按**章节频** `df ≤ ceil(5% × 章数)`（重叠窗口会把长章节同一个词数两遍，按块频会误杀长章节的线索）。
4. **罕见 ≠ 线索**：`r4_vague_terms.mjs` 对一句空洞方向的审计显示，33 个方向 n-gram 里 28 个
   「按 df 算罕见」，其中 27 个全书根本不出现，真正匹配的只有 2 字的「现有」（2 章里出现过）——
   就是它独自决定了 800 字注入。→ 加长度—唯一性阶梯：线索至少 3 个连续汉字，
   2 字词只有全书唯一才放行（`MinClueRunes=3`，ASCII 整词不受限）。
   没有这个豁免时，两字人名这类短线索会从 42% 掉到 4%。

代价与收敛：`gate_check` 里无方向线索的方向 `recallUsedChars=0`、正文窗口回到 8973 字（预算完整归还）；
带线索的方向只按实际相关块注入（样例 191 字 / 1 次命中），不再无条件填满 800 字。

## 5. 已证 / 未证

- **已证（离线 + 真实语料 + 只读预览）**：埋点召回从 19%→96%（3-gram）、4%→42%（2-gram）；
  注入闸能把无线索方向的正文成本降为 0；同一输入 5 次排序一致（确定性）。
- **未证**：注入更相关的前文是否真的提升续写文学质量——需要模型 Key 跑
  `longeval -stops recall-on,recall-off` + `evalreview -axis recall` 的人工 A/B，通道仍被阻断。
- **不代表 G1 跑通**：语料 17.7 万字，不是 500 万字目标；5M 字一次性重建索引的成本仍未量。
- **两字线索 38%–42% 是已知上限**：无分词的 n-gram 召回分不清「全书唯一的 2 字专名」和
  「全书唯一的 2 字偶然组合」，这块收益应交给 G2/G3 的结构化实体记忆，而不是继续调 n-gram。

## 6. 建议冻结的回归判据

- 3 字埋点命中率 ≥ 0.90（当前 0.96 / 1.00）
- 2 字埋点命中率 ≥ 0.40（当前 0.42 / 0.38，`contextChars=4000` 档需在下一轮补样本再定）
- 无线索方向注入字数 == 0
- 同一输入 5 次排序一致
- 合成语料里每条带线索方向的**过闸章数 == 1**（只由命中率把关会漏掉闸门放宽，见 §7 反向验证）

## 7. 回归

- `gofmt -l internal/recall` 无输出；`go vet ./...` 通过
- `go test ./... -count=1` 9 包全绿
- `CGO_ENABLED=1 go test -race ./... -count=1`（mingw-w64 gcc 15.2.0）9 包全绿，耗时见 `../r4-race.txt`
- 新增/改写单测：`TestSearchRequiresCluePhraseLength`（长度—唯一性阶梯）、
  `TestSearchDropsHitsWithoutRareClue`（无线索不注入）、`TestSearchRepeatedClueOutranksSingleMention`（真实 tf）、
  `TestSearchIntentWeightingOutranksRecentNoise`（改写为新闸门语义）
- **命中率判据入库**（2026-10-24 收尾）：`TestSearchPlantedClueRateOnSyntheticCorpus`
  把上面第 6 节的判据变成会红的测试——合成 60 章 / 约 3.5 万 rune 语料（跨章通用句 + 中频母题 +
  末 5 章只属于自己的独特正文），埋 20 条全书唯一的三字线索，逐条按生产语义探针
  （查询=末 5 章正文，方向=引用该线索），断言 ① 目标章召回率 ≥ 0.90（实测 20/20）
  ② 每条方向**只有目标章过闸**（`len(hits)==1`）③ 片段含埋点原句 ④ 同输入两轮逐条一致
  ⑤ 模糊方向（只共享两章的「现有」残片）与完全无共享的方向各 0 注入
  ⑥ 语料前提自检：模糊方向与正文的罕见共享词只允许「现有」一条。
- **反向验证**（临时把 `defaultMinClueRunes` 从 3 降到 1 跑一轮，随后还原）：命中率仍是 1.0
  ——目标章排序没塌——但 20 条探针全部 `hits=2`（三字线索的前两字与相隔 10 章的同族线索重复，
  df=2 就够开闸），`len(hits)==1` 这条先报警。结论：**长篇埋点召回的回归不能只监控命中率，
  必须同时监控「有几章过了闸」**，否则闸门放宽在同族线索下不会体现在排序上。
  这条不变式正是为这类失效准备的。
